The 4 features, in plain words

Feature 1

Talking to Michael — he'll actually know what's going on

Today, when you press talk, Michael gets one sticky note at the start of the call ("5 agents, 2 tasks running") — and then learns nothing new. Every question you ask forces him to put you on hold and go look it up. And he can only do a handful of things.

Why this way? The voice API charges almost nothing for things Michael has already heard (99% discount), but re-writing his briefing mid-call throws that discount away. So we never rewrite — we only append whispers. Cheap and fast.

New powers he'll get (each behind the same safety gate that exists today): un-pause agents, clear an agent's memory-of-the-conversation, restart an agent on a different model, change settings (from an approved list only — never passwords or keys), manage tasks and schedules.

Feature 2

Settings — from junk drawer to labeled drawers

Right now "General" holds six unrelated things, some switches shown there can't actually be flipped, and a few important settings have no switch anywhere (you'd have to edit a hidden file). The redesign sorts everything into six drawers that match how you think.

Bonus: the research found real bugs. Four settings show the wrong state or contradict their own documentation — e.g. one toggle displays OFF while it's actually ON. Those get fixed as part of this work.
≈ 3–4 daysno risky changesfixes 4 config bugs
Feature 3

Markdown preview — see the document, not the raw text

Agents constantly write reports and docs as .md files. Today you see them as raw text with # and * symbols. This feature shows the cooked page — headings, tables, checklists — in two places:

Safety note that drove the choice: agents write these files, so we treat them as untrusted. The renderer we picked can't run hidden scripts even in theory — it never converts the file to raw web code at all.
≈ 3–5 daysreuses an existing overlayfastest visible win
Feature 4

Git time-machine — see every change, compare, jump back

Your agents make lots of code changes across branches. You'll get a visual map: the history of commits as a graph, click any commit to see exactly what changed, compare two branches side by side, and safely jump to any point.

Safety first: "jump to a commit" only works when the working folder is clean and no agent is running there — the app checks in its trusted core, so a bad click can never yank code out from under a working agent.
≈ 6–8 days40% pre-builtall diffs in the editor you already have
Bonus

What we learned from YC's "qm"

Y Combinator open-sourced qm, the agent-team tool they run their own company on. We studied all of it. Two headlines:

  • You're ahead of them in two areas — qm has no voice control and no git visualization at all. Your two hardest features have no reference to copy; they're differentiators.
  • Worth borrowing (as ideas, not code): a single 3-position safety dial (ask-first / normal / unrestricted) with a short list of commands that are never allowed no matter what · "watches" that trigger an agent when something happens (tests go red, a file changes) · a screen where you manage and share agent skills · making sure queues and tasks survive an app crash.
