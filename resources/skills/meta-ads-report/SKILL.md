# Meta Ads performance report

When you answer a question about ad **performance** with the Meta Ads tools
(`mcp__atmt-meta-ads__*`), your final deliverable is an **HTML report**, not a
chat table. A one-number question ("what did I spend yesterday?") can be
answered in one line; anything with a date range, several campaigns or a trend
gets the report.

If no `mcp__atmt-meta-ads__*` tools are in your tool list, the connector is off
or has no token: say so and stop. Never ask for or handle a Meta token yourself.

## Read only

This skill is for reporting. Do **not** call any tool that creates, updates,
activates, duplicates, deletes or boosts anything (`ads_create_*`,
`ads_update_*`, `ads_activate_entity`, `ads_duplicate_entity`, `*_delete*`,
`ads_boost_*`) as part of a report. Those spend money or change live ads; do
them only when the human asked for that exact change in plain words. Put
suggested changes in the report's `recommendations` instead.

## Steps

1. **Get the data.** List ad accounts, pick the one the human named (ask if
   there are several and they did not say). Pull insights for the date range
   they asked for (default: last 7 days, plus the 7 days before it for the
   deltas): totals, a per-day series, and rows at **three levels**
   (campaign, ad set, ad) with spend, impressions, frequency, clicks, CTR,
   CPC, results, cost per result and ROAS when the account tracks purchase
   value. Use the account's own currency.
2. **Copy the template.** Copy `template.html` from this skill's folder to
   `reports/meta-ads-<account-slug>-<since>_<until>.html` inside your working
   folder (create `reports/`).
3. **Fill the data. Edit only the JSON inside `<script id="report-data">`.**
   Leave the styles, scripts, Chart.js tag and footer as they are: they carry
   the brand, the charts, the Save as PDF button and the "Report generated by
   DevLabs" footer.
   - `account`, `currency` (ISO code), `dateRange.since/until` (YYYY-MM-DD),
     `resultLabel` (e.g. "Purchases", "Leads"), `generatedAt` (ISO time now).
   - `summary`: 1–3 plain sentences: the headline number, what changed, the
     biggest lever.
   - `kpis`: up to 8 cards. `format` is `money`, `int`, `pct` (a fraction:
     0.0142 = 1.42%), `x` (ROAS) or `num`. `delta` is the change vs the
     previous period as a fraction (0.12 = +12%); leave it out when there is no
     comparison. Set `lowerIsBetter: true` for costs (CPC, CPM, cost per
     result). Mark the one most important card `key: true`.
   - `daily`: one row per day, `{ "date", "spend", "results" }`.
   - `campaigns`, `adsets`, `ads`: one row per entity with the fields shown
     in the template. Ad sets also carry `campaign` (its campaign's name), ads
     carry `adset`. `frequency` is optional. Include every campaign and ad
     set that spent in the period; for ads, the top 25 by spend. Each level
     becomes a tab (Campaigns / Ad sets / Ads); the cheapest cost per result
     is highlighted and the cost-per-result chart follows the selected tab.
     A level with no rows (`[]`) is left out. Use the ad-set and ad rows for
     the analysis: the winning and wasting ads are usually found there.
   - **Analysis is required, not optional.** Fill all three lists from the
     data you pulled, each item `{ "title", "text", "metric" }` (`metric` is a
     short number line such as "CPR $12.73 vs $14.19 avg"):
     - `findings`: 2–5 things that are working or worth knowing (best
       campaign, best day, audience or placement that wins).
     - `issues`: every problem you find, each with `"severity"`: `high`
       (wasting money now: spend with no results, CPR far above average,
       ROAS under 1, ad rejected or in learning-limited, budget exhausted),
       `medium` (falling CTR, rising CPM or frequency, creative fatigue,
       tracking gaps) or `low` (minor). Check delivery status and errors
       (`ads_get_errors`, entity status) as well as the numbers. If there
       really are none, use `[]`; the report then says so.
     - `recommendations`: 2–5 concrete next actions, each tied to a finding
       or issue, with the expected effect.
   - Never invent numbers; use `null` for anything the API did not return (it
     shows as "—").
   - It must stay valid JSON. Write every `<` inside a string as `<` (so a name like `</script>` cannot end the data block). JSON reads it back as `<`.
4. **Check it.** Run
   `node -e "JSON.parse(require('fs').readFileSync(process.argv[1],'utf8').match(/id=\"report-data\"[^>]*>([\s\S]*?)<\/script>/)[1])" <file>`
   and fix the JSON until it prints nothing.
5. **Open it in the browser** (the human's default browser):
   - Windows: `cmd.exe /c start "" "<absolute path to the .html>"`
   - macOS: `open "<path>"`
   - Linux: `xdg-open "<path>"`
6. **Deliver it.** Hand the file to the human as a delivery (a "done" message
   with `"attachments": ["reports/<file>.html"]`, see PROTOCOL.md) so it lands
   in their Deliveries tray, and reply with the path plus a 2–3 line summary.

## What the human gets

- Volt Dark branding (warm near-black, one volt-green accent, Inter Tight and
  JetBrains Mono).
- One compact page: key-number cards with period-over-period change, then
  Findings / Issues (sorted by severity) / Recommendations side by side, then
  an animated daily spend vs results chart, a spend-share doughnut, the
  campaign table and a cost-per-result bar chart.
- **Save as PDF**: the button opens the print dialog; choose "Save as PDF".
  The page prints in landscape with the dark theme kept and the button hidden.
- Footer: "Report generated by DevLabs" and the time it was generated.

Charts load Chart.js 4.6.2 from jsDelivr (pinned, integrity-checked). Offline,
the report still shows every number and a short note in place of the charts.
